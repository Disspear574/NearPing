 Обнаружение

Сервис Bonjour / DNS-SD: `_nearping._tcp`, домен `local.`

TXT-запись:

| Ключ | Значение |
|---|---|
| `v` | версия протокола, сейчас `1` |
| `pk` | публичный ключ Ed25519 (Curve25519 signing), base64url без выравнивания |
| `n` | отображаемое имя, UTF-8 |

Больше в TXT не кладётся ничего. Запись видна **всем** в сети, а не только контактам,
поэтому статус паузы и любые другие сведения о человеке передаются только по установленному
доверенному соединению.

Пир узнаётся по `pk`, а не по адресу, имени сервиса или имени машины. Смена IP, рандомизация
MAC и переезд в другую сеть не считаются сменой личности.

Запись с `v`, отличным от своего, игнорируется целиком.

 Обрамление потока

TCP не сохраняет границ сообщений, поэтому каждое сообщение предваряется длиной:

```
+--------+--------+--------+--------+---------------------------+
| len[3] | len[2] | len[1] | len[0] |   payload (len байт)      |
+--------+--------+--------+--------+---------------------------+
```

- Длина — беззнаковое 32-битное целое **big-endian**.
- Максимум — **65536** байт. Кадр длиннее не отправляется и при приёме считается ошибкой:
  объявленная длина приходит из сети, и без верхней границы чужой пакет заставит получателя
  копить память в ожидании тела, которого не будет.
- Получатель обязан собирать кадры из произвольно нарезанных кусков: один `read` может
  принести половину кадра, полтора кадра или три кадра сразу.

 Конверт

Тело кадра — UTF-8 JSON:

```json
{ "v": 1, "body": { "type": "ping", "id": "p1", "urgent": true } }
```

- `v` обязателен в каждом сообщении. Несовпадение с собственной версией — ошибка,
  соединение закрывается. Молча игнорировать нельзя: иначе разные версии будут
  наполовину понимать друг друга.
- Поле `type` внутри `body` различает вариант сообщения.
- Неизвестные поля игнорируются — это позволяет добавлять необязательные поля,
  не ломая старых клиентов.

 `auth_challenge` / `auth_response`

Челлендж-ответ с выводом ключа сессии. Обе стороны сразу после `hello` шлют свой
`auth_challenge`; каждая отвечает на чужой вызов `auth_response`.

```json
{ "type": "auth_challenge", "challenge": "<base64url, 32 случайных байта>" }
{ "type": "auth_response",
  "challenge": "<тот же вызов>",
  "ephemeralKey": "<base64url, публичный ключ X25519 на это соединение>",
  "signature": "<base64url, подпись Ed25519 над challenge ‖ ephemeralKey>" }
```

Правила:

- Челлендж **одноразовый**. После первой проверки он вычёркивается, повторное предъявление
  той же пары челлендж-подпись отвергается. Иначе подслушанный обмен переиспользуется.
- Подпись проверяется публичным ключом из `hello` этого же соединения и покрывает
  **и вызов, и эфемерный ключ** — без этого посредник подменил бы ключ и слушал обе стороны.
- Ключ сессии выводится обеими сторонами из X25519 своих и чужих эфемерных ключей;
  подробности — в разделе «Шифрование сессии».
- Приватный ключ личности на провод не попадает никогда.

 Шифрование сессии

Рукопожатие устанавливает не только «кто на том конце», но и ключ для всего дальнейшего обмена.

1. Каждая сторона создаёт **эфемерную** пару X25519 на это соединение.
2. Публичная часть эфемерного ключа передаётся в `auth` и **подписывается постоянным ключом**
   личности. Подпись связывает эфемерный ключ с личностью — без неё посредник подменил бы
   ключ и слушал обе стороны.
3. Обе стороны выводят общий секрет X25519 и из него — ключ сессии.
4. Все кадры **после** рукопожатия запечатываются ChaChaPoly. Внутри кадра лежит
   `nonce ‖ ciphertext ‖ tag`, а не открытый JSON.

Зачем это нужно, если в сообщениях нет тайн: без запечатывания подтверждена только личность
**в момент соединения**, а дальше поток ничем не защищён — на коммутируемой сети посредник
может вклиниться в установленное соединение и слать вызовы от чужого имени. Печать привязывает
каждый кадр к тому, кто прошёл проверку.

Обмен `hello` и `auth` идёт открытым текстом — до вывода общего ключа шифровать нечем.
Эфемерные ключи не сохраняются: соединение разорвано — расшифровать записанный трафик
задним числом нечем даже владельцу постоянного ключа.

 Следствие для экспортного соответствия

Это **не-освобождённая** криптография: свой обмен ключами и своё шифрование, а не системный
TLS. При раздаче вне App Store вопрос не задаётся, но для App Store потребуется
`ITSAppUsesNonExemptEncryption = true` и годовой self-classification report.
